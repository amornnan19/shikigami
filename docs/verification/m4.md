## Manual run

- Date: 2026-11-28
- Claude Code CLI: 2.1.332
- Model: `claude-haiku-5-5`
- Sign-in mode: Claude subscription (the app setting and both agents were set to it in a temp data
  folder; the Keychain was not read)
- Data, workspaces and groups folders: temporary. The group "Team" used the folder the dialog
  suggested; it held `alpha.txt`, `beta.txt` and a `CLAUDE.md` whose first line is
  "ZEBRA-QUARTZ-4471 is the code word of this folder."
- Real turns (8, the limit), in order:
  1. Group, "hello": Ada answered (check 2).
  2. Group, "@Bo list the files in this folder": Bo ran one `ls -la` step in the group folder and
     listed `alpha.txt`, `beta.txt`, `CLAUDE.md` (checks 3 and 9).
  3. Group, "@Ada Ask Bo to read the CLAUDE.md here and tell you its first line, then tell me":
     Ada handed the task to Bo, Bo answered with the first line, Ada continued with it (check 4).
     Bo opened its reply with "@Ada", which is itself a hand-off, so the group ran five turns for this
     one message (Ada, Bo, Ada, Bo, Ada) before it settled.
  4. Ada's own chat, "my secret word is plum": answered. The database then showed one-to-one
     session `040e18e5...` for Ada and group session `8aaf0230...`, so the two are separate
     (check 7).
- The message of step 3 starts with "@Ada" because a user message that mentions Bo addresses Bo,
  not Ada.
- Check 7, group side: the 8 turn limit was used up by the longer hand-off in step 3, so "what is
  my secret word?" was not asked in the group on the real CLI. Separation of the sessions is shown
  by the session ids and by the e2e test.
- Empty file listing seen in #66: not reproduced. The one tool step of step 2 was
  `ls -la <group folder>` with the group's real path and returned the three files.
